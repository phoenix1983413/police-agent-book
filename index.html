一、总体架构设计

1.1 架构设计原则

本系统采用五层架构设计，从基础设施到业务应用逐层抽象，确保系统的可扩展性、可维护性和安全性。架构设计遵循以下核心原则：

  • 分层解耦：每层职责明确，通过标准化接口通信，支持独立升级
  • 安全可信：数据分级分类、全链路审计、涉密数据不出域
  • 模块化演进：支持从MVP到全功能的分阶段迭代
  • 高可用：关键组件冗余部署，支持故障自动转移

1.2 五层架构总览

层级 核心组件 技术选型
业务应用层 情指行一体化、合成作战、重点人管控、沙盘推演、风险预警 Vue.js 3 + Element Plus
智能体编排层 任务编排引擎、Skill调度、技战法工场、多Agent协同 LangGraph + 自研状态机
能力引擎层 垂直警务大模型、六维标签引擎、时空计算引擎、可信推理引擎 Qwen/DeepSeek + PGVector
底座支撑层 可信数据协同、虚实融合训推平台、业务系统网关 RabbitMQ + 私有化训推一体
基础设施层 GPU集群、对象存储、向量库、时序库、图数据库、权限审计 K8s + Milvus + Doris

1.3 架构演进路径

系统采用渐进式架构演进策略，避免一次性重构风险：

阶段一（0-3月）：数据底座建设 → 阶段二（2-5月）：垂直模型构建 → 阶段三（4-7月）：智能体引擎 → 阶段四（6-10月）：场景落地

二、核心模块设计

2.1 全域任务编排引擎

基于LangGraph实现的任务编排引擎，支持复杂业务需求的自动拆解与执行。

class TaskOrchestrator:
    def __init__(self):
        self.state_machine = StateMachine()
        self.skill_registry = SkillRegistry()
        self.agent_pool = AgentPool()
    
    async def execute(self, task: Task) -> TaskResult:
        # 任务拆解
        subtasks = await self.decompose(task)
        # 状态机调度
        return await self.state_machine.run(subtasks, self.agent_pool)

2.2 可信数据协同模块

实现数据跨域访问控制、隐私计算、数据可用不可见。采用联邦学习与安全多方计算(MPC)技术，确保多方数据协同研判时原始数据不跨库导出。

2.3 六维标签引擎

针对警务业务场景，构建人、事、地、物、组织、时间六维标签体系。采用规则+模型联合打标策略，标签存入图数据库+向量库，支持实体关联分析与画像构建。

2.4 时空计算引擎

基于PostGIS和Doris实现时空数据分析，支持轨迹分析、区域热力、时空碰撞、空间圈层研判等核心算法，输出空间风险指标。

2.5 技战法工场

可视化Skill生产平台，业务专家可通过拖拽方式编排警务技能，实现50+实战Skill的快速开发、版本管理与灰度发布。

2.6 指令转换网关

模型输出的结构化指令经网关校验鉴权后，翻译为各业务系统API调用参数，实现从自然语言到业务系统执行的完整闭环。

三、数据架构设计

3.1 数据分级分类

警务数据按敏感程度分为四级：公开、内部、敏感、机密。不同级别数据对应不同的存储、传输和访问控制策略。

3.2 存储选型

数据类型 存储方案 用途
向量数据 Milvus / PGVector 法条、案卷文本检索
图数据 NebulaGraph / Neo4j 人员关系网络、重点人关联分析
时空数据 Doris + PostGIS 轨迹、区域风险、时空碰撞
业务主库 MySQL / 达梦 警情、案件、人员结构化数据

3.3 数据治理流程

建立完整的数据治理流水线，涵盖数据采集、清洗、脱敏、打标、入库全流程，确保数据质量与安全合规。

四、技术栈选型

4.1 核心技术栈

层级 技术选型 选型理由
大模型基座 Qwen2.5 / DeepSeek-V2.5 国产开源、中文能力强、支持私有化部署
微调框架 LLaMA-Factory / Unsloth 支持SFT、DPO、量化训练，效率高
编排引擎 LangGraph + 自研状态机 可视化编排、支持复杂多Agent协作
向量数据库 Milvus 高性能、支持大规模向量检索
图数据库 NebulaGraph 原生分布式、高性能图查询
后端服务 Go-zero / FastAPI 高性能微服务、支持高并发

4.2 选型权衡

在模型选型上，优先选择国产开源基座，避免外部API依赖；在存储选型上，优先支持国产品牌（达梦、NebulaGraph），确保供应链安全。

五、安全合规设计

5.1 等保三级合规

系统按照网络安全等级保护三级要求设计，涵盖物理安全、网络安全、主机安全、应用安全、数据安全五个层面。

5.2 数据安全

  • 数据脱敏：敏感字段自动屏蔽，支持动态脱敏
  • 访问控制：细粒度RBAC权限模型，支持数据级权限
  • 操作审计：全链路操作日志，支持行为追溯
  • 数据加密：传输加密(TLS 1.3) + 存储加密(AES-256)

5.3 模型安全

采用DPO偏好对齐、RAG事实约束、输出事实引用、高危结论人工复核等多层防护机制，确保模型输出安全可靠。

六、部署拓扑

6.1 网络拓扑

采用内外网隔离架构，核心业务系统部署在内网，通过业务网关与外部系统交互。GPU集群独立部署，支持模型训推一体。

6.2 容器化部署

基于Kubernetes实现容器化编排，支持自动扩缩容、滚动更新、故障自愈。关键服务采用多副本部署，确保高可用。

6.3 资源规划

资源类型 配置要求 用途
GPU服务器 NVIDIA A100 80G × 8 模型训练与推理
高内存服务器 256GB RAM × 4 向量库、图数据库
存储服务器 100TB SSD × 3 业务数据、模型存储

八、MVP验证方案

8.1 验证场景

选取重点人风险预警作为MVP验证场景，端到端响应时间≤10秒。

8.2 MVP范围

  • 接入3-5个核心业务数据源
  • 构建基础六维标签体系
  • 基座+RAG + 2-3个核心Skill
  • 简易编排引擎实现任务拆解
  • 自然语言指令→标签查询→风险输出→预警下发

8.3 成功标准

MVP验证通过标准：系统能够准确识别重点人风险特征，预警准确率≥85%，响应时间≤10秒，支持人工复核。

十、风险与监控

10.1 关键风险

  • 幻觉风险：警务场景幻觉可能造成严重后果，需多层防护
  • 数据安全：涉密数据严禁出内网，需严格访问控制
  • 接口异构：各业务系统接口标准不一，需统一适配网关
  • Skill维护：50个Skill需逐步沉淀，避免一次性开发

10.2 监控指标

指标类别 监控内容
模型性能 响应时间、吞吐量、GPU利用率
业务质量 准确率、召回率、幻觉率
系统可用性 服务可用率、错误率、延迟
安全合规 访问审计、异常检测、数据脱敏率
