1. 文档概述

1.1 项目定位

本项目面向公共安全领域，构建垂直大模型 + 警务行业智能体的完整技术体系。核心定位是：

  • 非从零预训练基座：基于国产开源大模型基座（Qwen / DeepSeek 等），通过领域持续微调构建警务垂直模型
  • 智能体闭环：从自然语言问答 → 业务指令生成 → 业务系统执行，形成完整闭环
  • 强合规底座：所有数据、模型、调用链路满足等保、警务数据安全规范，涉密数据不出域

1.2 设计目标

目标维度量化指标
场景覆盖情指行一体化、合成作战、重点人管控、沙盘推演、风险预警 5 大核心场景
模型能力警务术语理解准确率 ≥ 95%；指令生成准确率 ≥ 92%；幻觉率 ≤ 3%
响应时效问答场景 P95 ≤ 3s；指令下发 P95 ≤ 5s；时空计算 P95 ≤ 8s
合规要求等保三级；全链路可审计；敏感数据脱敏率 100%
可扩展性支持 50+ 警务 Skill 快速编排上线

1.3 适用范围

本文档面向以下角色：

  • AI 算法团队：模型微调、RAG 建设、Prompt 工程
  • 大数据团队：数据接入、治理、图/时空数据库
  • 后端架构团队：智能体编排、指令网关、微服务、权限审计
  • 前端团队：技战法工场、沙盘可视化
  • 行业专家：标注样本、定义技战法、校验输出
  • 安全/运维：私有化集群、等保、审计、模型安全

2. 总体架构设计

2.1 架构原则

  1. 合规优先：数据不出域、全链路审计、私有化部署
  2. 分层解耦：五层架构，层间通过标准接口通信
  3. 渐进演进：从 MVP 闭环验证，逐步扩展到全场景
  4. 可追溯：所有架构决策记录 ADR，支持回访与演化
  5. 安全为底线：从设计阶段嵌入安全控制，不事后修补

2.2 分层架构总览

系统采用自顶向下五层架构：

┌─────────────────────────────────────────────────────────────────────┐ │ 业务应用层 │ │ 情指行一体化 │ 合成作战 │ 重点人管控 │ 沙盘推演 │ 风险预警 │ └─────────────────────────────────────────────────────────────────────┘ ↓ ┌─────────────────────────────────────────────────────────────────────┐ │ 智能体编排层 │ │ 任务编排引擎 │ Skill 调度 │ 技战法工场 │ 多 Agent 协同 │ └─────────────────────────────────────────────────────────────────────┘ ↓ ┌─────────────────────────────────────────────────────────────────────┐ │ 能力引擎层 │ │ 垂直警务大模型 │ 六维标签引擎 │ 时空计算引擎 │ 可信推理引擎 │ └─────────────────────────────────────────────────────────────────────┘ ↓ ┌─────────────────────────────────────────────────────────────────────┐ │ 底座支撑层 │ │ 可信数据协同 │ 虚实融合训推平台 │ 业务系统网关 / 指令转换器 │ └─────────────────────────────────────────────────────────────────────┘ ↓ ┌─────────────────────────────────────────────────────────────────────┐ │ 基础设施层 │ │ GPU 集群 │ 对象存储 │ 向量库 │ 时序库 │ 图数据库 │ 权限审计 │ └─────────────────────────────────────────────────────────────────────┘

2.3 层间职责与边界

层级核心职责边界约束
业务应用层面向最终用户的业务场景界面与交互不直接访问基础设施，通过编排层调用能力
智能体编排层任务拆解、Skill 调度、多 Agent 协同、状态管理不存储业务数据，编排结果可审计
能力引擎层模型推理、标签抽取、时空计算、可信校验模型输出结构化指令，不直接操作业务库
底座支撑层数据治理、训推一体、指令网关、权限控制涉密数据不出域，所有操作留痕
基础设施层算力、存储、数据库、网络内网隔离，最小权限原则

3. 核心技术模块设计

3.1 全域任务编排引擎

职责：接收高层业务意图，LLM 负责任务拆解，状态机管理子任务执行、失败重试、任务回溯，支持多 Agent 协同。

3.1.1 核心流程

用户意图 ↓ [LLM 任务解析] → 生成子任务列表 + 依赖关系 ↓ [状态机调度] → 按依赖顺序执行子任务 ↓ [工具调用层] → 调用六维标签引擎 / 时空计算引擎 / 图查询 ↓ [结果聚合] → 汇总子任务结果，生成最终响应 ↓ [指令网关] → 转换为业务系统 API 调用（如需）

3.1.2 技术选型

  • 底层框架：LangGraph（状态机 + 图遍历）或自研轻量状态机
  • 任务存储：PostgreSQL（任务状态、执行日志）
  • 调度策略：拓扑排序 + 失败重试（指数退避）
  • 可观测性：全链路日志 + 任务回溯快照

3.2 可信数据协同模块

职责：数据分级分类、细粒度 RBAC 权限控制、数据脱敏、数据血缘追踪、隐私计算、全链路操作审计。

3.2.1 数据分级标准

级别定义访问控制存储要求
公开可对外发布的信息开放访问标准存储
内部部门内部使用authenticated + 授权加密存储
涉密敏感业务数据最小权限 + 审批流专用加密存储，不出域

3.2.2 核心组件

  • 数据脱敏引擎：基于规则 + LLM 的敏感信息识别与替换
  • 权限网关：统一鉴权入口，拦截未授权访问
  • 审计日志服务：所有数据访问、模型调用、指令下发均记录审计日志
  • 血缘追踪：记录数据从源到消费的完整链路

3.3 虚实融合训推平台

训练链路：真实脱敏业务数据 + 仿真模拟案情数据混合训练。

3.3.1 训练策略

  1. RAG 先行：先挂载法条、技战法、案卷知识，快速实现警务问答
  2. SFT 监督微调：教会模型理解警务术语、处置流程、输出结构化指令
  3. DPO 偏好对齐：基于专家标注，对齐正确办案逻辑，规避幻觉
  4. 虚实混合训练：脱敏真实样本 + 仿真案情样本混合，沙盘推演场景重点用仿真数据

3.3.2 推理服务

  • 框架：vLLM / TGI（高吞吐推理）
  • 部署：私有化 GPU 集群，K8s 编排
  • 特性：动态负载、模型热更新、推理日志全审计
  • 输出格式：优先输出标准化结构化 JSON 指令，供下游网关解析

3.4 六维标签引擎

基于警务经典六维：人、事、地、物、组织、时间

维度示例标签存储方式
人重点人员、涉毒人员、上访人员图数据库（Neo4j/Nebula）
事案件类型、警情等级、处置状态图数据库 + 向量库
地点位、区域、围栏、风险热区时空数据库（PostGIS）
物车辆、物品、设备、涉案财物图数据库
组织单位、团伙、利益链图数据库
时间案发时间、轨迹时间轴、时段规律时序数据库

打标策略：规则引擎（确定性规则）+ 模型打标（LLM 辅助）+ 人工校验（低置信度审核）+ 标签演化（版本管理）。

3.5 时空计算引擎

核心能力：轨迹分析、区域热力、时空碰撞、空间圈层研判、时空规律分析。

技术栈：PostGIS（空间索引）、Doris/ClickHouse（轨迹存储）、轨迹算法库（Douglas-Peucker、停留点检测）、可视化（Cesium / 高德 JSAPI / 天地图）。

3.6 技战法工场

定位：业务专家无需编码的可视化 Skill 生产平台。

核心功能：可视化编排（拖拽式 Skill 流程设计）、Skill 类型管理（查询/统计/时空分析/预警/指令下发/案卷摘要/沙盘推演）、版本管理（战法版本、上线灰度、效果评估）、模板市场（沉淀高频 Skill 模板）。

技术实现：React + AntV X6 / React Flow（前端）、Skill 元数据管理与版本控制（后端）、Skill 沙箱执行（运行时）。

3.7 指令转换网关（闭环关键组件）

职责：模型输出的结构化指令 → 校验鉴权 → 翻译成各业务系统 API 调用参数，权限校验、操作留痕、高危操作人工复核。

3.7.1 核心流程

模型输出 JSON 指令 ↓ [ schema 校验 ] → 非法指令拦截 ↓ [ 权限校验 ] → 操作者是否有权执行 ↓ [ 指令翻译 ] → 转换为目标系统 API 参数 ↓ [ 执行与回调 ] → 调用业务系统 → 记录结果 → 返回

3.7.2 安全控制

  • 高危操作拦截：涉及人员管控、案件状态变更等操作必须人工复核
  • 操作留痕：所有指令执行记录不可篡改，存入审计日志
  • 限流熔断：防止指令风暴击穿业务系统
  • 幂等性：同一指令多次执行保证结果一致

6. 安全与合规设计

6.1 合规要求

合规项要求实现方式
等保三级安全保护等级三级等保测评 + 差距整改
数据不出域涉密数据禁止出内网私有化部署 + 网络隔离
全链路审计所有操作可追溯审计日志 + 区块链存证（可选）
密钥管理密钥不硬编码KMS / Vault 管理
访问控制最小权限原则RBAC + ABAC 结合

6.2 安全架构

6.2.1 网络安全

  • 网络隔离：业务域、数据域、模型域三层隔离
  • 边界防护：WAF、入侵检测、流量清洗
  • 传输加密：全链路 TLS 1.3

6.2.2 数据安全

  • 加密存储：敏感数据 AES-256 加密
  • 脱敏处理：输出前自动脱敏（姓名、身份证、手机号等）
  • 数据销毁：退役存储介质安全擦除

6.2.3 模型安全

  • Prompt 注入防护：输入过滤 + 输出校验
  • 越狱防护：jailbreak 检测 + 拦截
  • 幻觉缓解：RAG 强约束 + 事实引用 + 人工复核

6.3 威胁建模（STRIDE）

威胁类型风险场景缓解措施
Spoofing（伪装）非法用户冒充警察强身份认证 + 警务证书校验
Tampering（篡改）篡改模型输出或指令输出签名 + 区块链存证
Repudiation（抵赖）操作后否认不可篡改审计日志
Information Disclosure敏感数据泄露数据脱敏 + 权限控制
Denial of Service模型服务被击穿限流熔断 + 降级策略
Elevation of Privilege低权限用户越权RBAC + 操作审批

  1. 数据源接入：结构化库（警情、人员、案件，CDC 采集）、非结构化（笔录、案卷、音视频转写）、时空数据（点位、轨迹、区域）
  2. 数据治理：数据清洗（去重、格式统一、敏感信息屏蔽）、六维标签体系构建（人、事、地、物、组织、时间）、数据集划分（RAG 库、SFT 数据集、仿真数据集）
  3. 存储建设：向量库（Milvus/PGVector）、图数据库（Nebula/Neo4j）、时空数据库（Doris + PostGIS）

交付物：48 类数据源接入完成；5 亿业务数据治理流水线；六维标签引擎；知识库向量库。

8.3 阶段2：垂直警务大模型构建（2~5 个月）

目标：基于开源基座构建警务垂直微调模型

关键任务：

  1. 基座选型与部署：国产大模型基座选型（Qwen2.5 / DeepSeek），私有化部署，本地推理
  2. RAG 先行：法条、技战法、案卷知识挂载，检索策略优化
  3. SFT 监督微调：警务样本收集与清洗，模型微调训练
  4. DPO 偏好对齐：专家标注，对齐办案逻辑，幻觉抑制验证
  5. 训推平台建设：训练框架部署，推理服务化（vLLM / TGI）

交付物：警务垂直微调模型、RAG 知识库、训推平台、模型安全审计模块。

8.4 阶段3：智能体引擎+技战法工场（4~7 个月）

目标：实现业务闭环（自然语言 → 模型拆解 → 调用工具 → 下发业务系统）

关键任务：

  1. 技战法工场建设：前端可视化编排界面、Skill 元数据管理与版本控制、Skill 运行时沙箱
  2. 全域任务编排引擎：LLM 任务拆解、状态机管理、多 Agent 协同
  3. 时空计算引擎：轨迹分析算法、区域热力计算、空间圈层研判
  4. 指令转换网关：结构化指令解析、业务系统适配器、权限校验与审计

交付物：技战法工场、智能体编排引擎、50+ 警务 Skill、业务系统指令网关。

8.5 阶段4：场景落地与迭代（6~10 个月）

目标：5 大核心业务场景上线，持续迭代

关键任务：

  1. 可信数据协同模块：数据跨域访问控制、隐私计算组件、全链路操作审计
  2. 场景验证与评测：业务专家评测（战法准确率、幻觉率）、安全评测（敏感信息泄露、违规指令拦截）、实战小范围试点 → 灰度扩大
  3. 持续迭代：业务实战样本回流、模型持续迭代、战法 Skill 更新

交付物：五大业务场景上线、完整运维监控体系、模型持续迭代流水线。

9. 最小验证 MVP（快速跑通闭环）

9.1 MVP 范围

建议首个试点场景：重点人风险预警

9.2 MVP 架构

用户输入："评估重点人张某的风险等级" ↓ [智能体编排] → 拆解为： 1. 查询六维标签（人） 2. 查询时空轨迹（地、时间） 3. 查询关联人员（关系网络） 4. 风险评分计算 5. 生成预警报告 ↓ [能力引擎] → 调用标签引擎 + 时空计算 + 图查询 ↓ [指令网关] → 将预警结果写入业务系统 ↓ 返回结果：风险等级（高/中/低）+ 关键因素 + 建议处置

9.3 MVP 技术栈（简化版）

组件选型说明

9.4 MVP 成功标准

  • 从自然语言到风险预警输出，端到端延迟 ≤ 10s
  • 标签准确率 ≥ 90%
  • 幻觉率 ≤ 5%（人工抽检）
  • 指令下发成功率 ≥ 99%
